## 📂 Core Data Dependencies & Formats

The environment heavily relies on an initial decision-point tracking table. You must provide this dataset to initialize the RL state.

### 1. Decision Points State Table (`RL_STATE_2020.xlsx`)
This is the core input table where each row represents a geographical decision unit (e.g., a county or grid cell). Ensure your table contains the following exact column names:

| Column Name | Type | Description |
| :--- | :--- | :--- |
| `point_id` | String/Int | Unique identifier for the geographical cell/county. |
| `Provence_num` | Int | Province Code (e.g., 44=Guangdong, 45=Guangxi, 46=Hainan, 52=Guizhou, 53=Yunnan). |
| `x` / `y` | Float | Longitude and Latitude coordinates. Used for meteorological data matching. |
| `Installed_onshorewind` | Float | Current installed capacity for onshore wind (MW). |
| `Installed_offshorewind`| Float | Current installed capacity for offshore wind (MW). |
| `Installed_pv` | Float | Current installed capacity for solar PV (MW). |
| `Potential_onshorewind` | Float | Maximum developable potential for onshore wind (MW). |
| `Potential_offshorewind`| Float | Maximum developable potential for offshore wind (MW). |
| `Potential_pv` | Float | Maximum developable potential for solar PV (MW). |

### 2. Meteorological & Profile Data
* **Weather Data (NetCDF)**: `windspeed_100m.nc` and `SOLARRAD_T2M_2013_2023.nc`. Must contain spatial coordinates (`lat`, `lon`) and an hourly `time` dimension.
* **Load Profiles**: Folder containing standardized 24-hour load curves for each province.

## 🧠 Training Organization & Architecture

The training process is modular and organized geographically. Instead of training a massive agent for the whole country, REX-Grid trains specialized agents for specific regions.

1. **Geographical Filtering (`province_num`)**:
   In `train_ppo_gd.py`, you specify the target province ID (e.g., `province_id=44` for Guangdong). The environment initialization automatically masks out all other regions, loading only the relevant rows from `RL_STATE_2020.xlsx` to form the action and observation space for that specific province.
2. **Parallel Environment Vectorization**:
   The framework utilizes `SubprocVecEnv` from Stable-Baselines3. It spawns multiple parallel workers (e.g., 32 processes) to interact with the environment simultaneously. This drastically reduces the time needed to collect trajectories (states, actions, rewards).
3. **PPO Agent**:
   A Proximal Policy Optimization (PPO) agent observes the remaining capacity margins and system complementarity indices (Kendall's Tau, CV, CI1, CI2) to output expansion decisions `[-1, 1]`, which are then scaled into actual MW additions.

## 🚀 Execution Flow

1. **Configure Paths**: Open `train_ppo_gd.py` and `compute_power_gap.py`, and update the absolute paths pointing to your local `RL_STATE_2020.xlsx` and NetCDF datasets.
2. **Set Target Region**: In the `main()` function of `train_ppo_gd.py`, change the `province_id` parameter to your desired target (44, 45, 46, 52, or 53).
3. **Run Training**:
   ```bash
   python train_ppo_gd.py
